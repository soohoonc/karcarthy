This guide defines one reviewer, runs it, and then gives it `eval`.

## Before you begin

You need JDK 21, the Clojure CLI, and an OpenAI API key.

## Add karcarthy

Create `deps.edn`:

```clojure title="deps.edn"
{:deps
 {io.github.soohoonc/karcarthy
  {:git/url "https://github.com/soohoonc/karcarthy"
   :git/sha "76468125d3c22c00c5a8e0e5d4c13bcee249ad30"}}
 :paths ["src"]}
```

Set the credential in the shell that starts Clojure:

```bash
export OPENAI_API_KEY="..."
```

## Define one agent

Create `src/example.clj`:

```clojure title="src/example.clj"
(ns example
  (:require [karcarthy :as k]))

(k/defagent reviewer
  {:model "gpt-5.6"
   :instructions
   "Review this pull request. Report concrete defects introduced by the patch
    and explain the evidence for each finding."})
```

`defagent` creates an agent value and derives its name from `reviewer`. Agent
input and output default to strings.

## Run it

Start a REPL:

```bash
clojure -M
```

Then run the reviewer:

```clojure
(require '[example :as example]
         '[karcarthy :as k])

(def review-request
  (str
   "Requirement: only admins may export customer data.\n"
   "Existing behavior: require-user authenticates but does not check roles.\n\n"
   "```diff\n"
   "+(defn export-customers [request]\n"
   "+  (let [user (auth/require-user request)]\n"
   "+    {:status 200\n"
   "+     :body (csv/encode (customers/all))}))\n"
   "```"))

(def result
  (k/run! example/reviewer review-request))
```

`run!` waits for the agent and returns a map:

```clojure
(:status result)       ;=> :completed
(println (:output result))
(:usage result)        ;=> {:model-calls ..., :input-tokens ..., ...}
```

Or use `output` when a failed run should throw:

```clojure
(k/output result)
```

Only one agent participates:

```text
run! reviewer
└─ reviewer → model → review
```

## Give it eval

Replace the definition with:

```clojure title="src/example.clj"
(k/defagent reviewer
  {:model "gpt-5.6"
   :instructions
   "Review this pull request. After reading the patch, decide what kind of
    review the change needs and use eval to author and run that reviewer. Pass candidate
    findings to an independent verifier and publish only verified defects."
   :tools [k/eval]})
```

Reload the namespace and run the same request:

```clojure
(require '[example :as example] :reload)
(k/output (k/run! example/reviewer review-request))
```

The reviewer now sees an `eval` tool. Its description teaches the model how to
write one Clojure expression using `agent`, `run!`, `output`, and the original
`input`.

For this patch, the reviewer may construct a `security-reviewer`, run it, then
construct a `verifier` and pass the candidate findings to it. Those agents are
not predefined by the application. The reviewer authors them after reading the
patch.

Agents created inside eval do not inherit eval. Add `:tools [eval]` to a
constructed agent only when it should be able to author another program.
