title: Build a coding agent
description: Run a multi-turn coding session with repository tools and optional eval.
---

## Start a session

Set `OPENAI_API_KEY`, change to a repository, and start the coding example:

```bash
clojure -M:examples coding
```

The current directory is the tool root. To work in another repository, pass it
explicitly:

```bash
clojure -M:examples coding cwd=/workspace/project
```

The command opens a prompt instead of running one fixed task:

```text
karcarthy coding
repository: /workspace/project
model: gpt-5.6
dynamic eval: off
local tool approvals: ask
conversation items: 0
Type /help for session commands.

you>
```

Conversation history is kept in a process-local `Session` and is discarded when
the process exits.

## Follow the work

During a turn, the Run monitor owns one live terminal region:

```text
Run run_123… · running · 4s · 1 model call · 0 tokens
└─ coding-agent · reasoning
   ↳ Inspecting the test command and the failing namespace.
```

The tree redraws in place instead of appending status lines. It shows model,
Tool, eval, and nested-Agent activity. When the provider supplies a reasoning
summary, the current summary appears under the Agent; this is not the model's
raw chain of thought. Approval prompts temporarily replace the tree, which is
redrawn after the answer. The final `agent>` response prints below the completed
tree.

The session commands are intentionally small:

| Command | Effect |
| --- | --- |
| `/status` | Show the repository, model, capabilities, conversation size, and last-run usage |
| `/diff` | Show tracked changes against `HEAD` |
| `/clear` | Clear the process-local conversation |
| `/help` | Show the command list |
| `/quit` | Exit |

## Approvals

By default, `read` and `search` run without a prompt. `write`, `edit`, and
`bash` show the proposed operation and require `y` or `yes`:

```text
approval> bash clojure -M:test
Allow this tool call? [y/N]
```

Any other answer denies the call. To run local tools without these prompts,
start the session with `approval=never`:

```bash
clojure -M:examples coding approval=never
```

This approval policy belongs to the example's local tools. Shell execution is
bounded but not sandboxed.

## Add dynamic programs

The ordinary coding session has five repository tools: `read`, `write`, `edit`,
`bash`, and `search`. It does not receive eval unless you request it:

```bash
clojure -M:examples coding dynamic=true
```

The example then adds `k/eval` to the same agent:

```clojure
(defn coding-agent [{:keys [cwd dynamic? approval]}]
  (k/agent
   {:name "coding-agent"
    :model {:transport :responses
            :provider :openai
            :id "gpt-5.6"
            :reasoning {:effort :medium
                        :summary :auto}}
    :instructions base-instructions
    :tools
    (cond-> (k/local-tools
             {:cwd cwd
              :needs-approval (approval-policies approval)})
      dynamic? (conj k/eval))
    :max-turns 24}))
```

With eval installed, the model may still solve a straightforward task directly.
For a task that benefits from independent investigation or review, it can
instead author one Clojure expression that constructs agents and calls `run!`.
Those calls share the root Run's limits, events, cancellation, and usage.

Eval is full-trust JVM Clojure, not a sandbox. Code executed through eval is not
governed by the local tools' approval prompts.

## Three focused local checks

### 1. Repository exploration and conversation

```bash
clojure -M:examples coding
```

At `you>`, enter:

```text
Inspect this repository. Explain how its tests are organized and cite the files
you used. Do not edit files.
```

Then ask:

```text
Which single test would you run first after changing the model loop, and why?
```

This checks repository reads and searches, streamed progress, and whether the
second turn uses the first turn's context.

### 2. Edit, approval, and verification

Use a repository where you are comfortable making a small change:

```bash
clojure -M:examples coding cwd=/workspace/disposable-project
```

At `you>`, enter:

```text
Find one small documentation error, fix only that error, and run the narrowest
relevant check.
```

Approve only operations you understand, then run `/diff`. This checks the
write or edit approval, shell approval, focused verification, and diff view.

### 3. Model-authored orchestration

```bash
clojure -M:examples coding dynamic=true
```

At `you>`, enter:

```text
Use eval to investigate the public API from two independent perspectives:
one agent should trace how a run executes, and another should assess whether
the documentation matches the implementation. Synthesize their evidence.
Do not edit files.
```

This checks explicit eval injection, model-authored Clojure, nested agents,
shared Run observation, and final synthesis.

Use the [Harbor integration](/docs/protocols/harbor) when the repository should
be isolated and a behavioral verifier should score the result.
