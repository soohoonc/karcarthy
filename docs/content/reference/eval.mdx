title: Eval
description: How an agent learns and executes model-authored Clojure.

## Enable eval

Eval is explicit:

```clojure
(k/agent
 {:name "reviewer"
  :model "gpt-5.6"
  :instructions "Review the change and use eval when another reviewer is useful."
  :tools [k/eval]})
```

Without `k/eval`, the model does not see an eval tool.

## What the model is told

`k/eval` begins as a capability marker. When the agent runs, karcarthy replaces
it with a tool generated for that agent.

The generated tool description tells the model:

- It may send exactly one Clojure expression.
- The current agent input is bound to `input`.
- `agent` and `tool` construct new values.
- `run!` runs an agent and `output` extracts a completed result.
- Normal Clojure such as `let`, `if`, collections, `future`, and `deref` is
  available.
- Nested calls join the active run but start fresh model conversations.
- Evaluated code is full-trust JVM Clojure.

The description also includes the current model configuration and lists tools
and agents supplied by the application. This is how the model learns the API;
it is not expected to infer the syntax from the tool name.

## Tool input

The model calls eval with:

```clojure
{:code "(+ 1 2)"}
```

The input schema accepts only the string field `code`. The string must contain
one top-level expression. A `let` or `do` may contain an entire program while
still satisfying that rule.

Empty input, extra expressions, and reader evaluation are rejected.

## Evaluation namespace

The expression receives these bindings:

```clojure
agent
defagent
tool
deftool
run!
output
context
definition
expansion
eval
input
```

It also receives public values from the namespace where the parent agent was
defined, plus the tools and agents catalogued in the generated eval
description.

An agent created by the expression does not inherit eval. Give it
`:tools [eval]` only when it should be able to author another program.

## Processing

For each call, karcarthy:

1. consumes one unit from the run's `:evals` limit;
2. reads exactly one expression with `*read-eval*` disabled;
3. macroexpands executable positions while preserving quoted data;
4. evaluates the expression with the active run bound; and
5. converts its returned value into data the model transport can encode.

Constructing an agent does not run it. The expression must call `run!`.

## Run participation

A nested `run!` returns a normal run map and participates in the active run.
It shares the run ID, limits, usage, events, cancellation, approvals, context,
and executor.

Each participating agent receives only its explicit input and begins a fresh
model conversation. It does not inherit the parent model's messages.

## Events

| Event | Meaning | Fields |
| --- | --- | --- |
| `:eval/started` | Evaluation started. | `:code`, `:input` |
| `:eval/expanded` | Reading and macroexpansion succeeded. | `:expression`, `:expansion`, `:namespace` |
| `:eval/completed` | Evaluation and result conversion succeeded. | `:value`, `:duration-ms` |
| `:eval/failed` | A phase failed. | `:phase`, `:error`, `:duration-ms` |

See [Events and monitoring](/docs/events) for the complete event list.

## Trust

Reader evaluation is disabled while reading source, but the resulting
expression is deliberately executed with `clojure.core/eval`. This is not a
sandbox. It has the filesystem, network, credentials, classpath, and other
authority of the karcarthy process.
